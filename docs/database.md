# Legacy database: facts that shape the port

Surveyed 2026-09-22 against a local restore of `DBLibSQL` (SQL Server 2025, Linux).
Re-check these before relying on them for a specific table.

## Shape

- 412 user tables, all in `dbo`, plus 5 views, 173 stored procedures, 17 functions
  and 5 triggers.
- Collation `SQL_Latin1_General_CP1_CI_AS`, so comparisons are **case-insensitive**.
  Gujarati text is `nvarchar` and round-trips intact through tedious (covered by
  `apps/api/test/db.integration.test.ts`).
- The DB holds dated backup copies (`VishayEntry_20072024`, `VishayEntry_rev1234` …)
  and 17 `*Del` / `*_del` shadow tables. They appear in the generated types; don't build
  screens on them without checking what the desktop app uses.

## Keys and IDs

- **150 tables have no primary key.** Kysely is used because it works with them, where
  Prisma would skip them.
- 213 tables have an identity column (`Usecurity.tid` is one of them). The rest, including masters such as `bhasmast`
  (`bhashacokm`), get **IDs generated by the application**. Port each screen's ID
  generator exactly. While the desktop app writes to the same DB, generate IDs inside a
  transaction that locks the rows it reads (`WITH (UPDLOCK, HOLDLOCK)`), so the two apps
  can't hand out the same ID.

## Types the generated schema gets wrong

- `bigint` columns (`log.logID`, `work.workID`, …) arrive from tedious as **strings**,
  though `packages/db` types them as `number`. Convert with `Number()`.
- `date` and `time` columns arrive as JS `Date`s in UTC, which shifts easily. In queries,
  read them with `CONVERT(varchar(10), col, 23)` / `CONVERT(varchar(8), col, 108)`, and
  pass them in as ISO strings wrapped in `CAST(... AS date|time)`. Never pass a JS `Date`.
- "Today" and "now" come from the SQL Server clock (`GETDATE()`), as on the desktop, and
  never from the API host. See `serverNow()` in `apps/api/src/db/legacy-sql.ts`.

lookups and search columns. `Config_Master` holds the saved print layouts.
